Say this at the start

"Every router on the Internet answers one question for every packet: which way does this go? Onyx is not a router, but it answers the same question the same way, so today we ask it. Everyone ssh onyx. Predict before we run anything." Then hand out the sheet.

Round 1 · Onyx's address

ip -4 -br addr
lo               UNKNOWN        127.0.0.1/8
eno12399np0      UP             132.178.227.11/25
Say "A /25 is 25 network bits and 7 host bits. Do not recall it, derive it."
Subnet size. 27 = 128 addresses, 126 usable (network and broadcast are reserved).
Binary. 11 = 0|0001011. The mask's last octet is 1|0000000 = 128, so the mask is 255.255.255.128.
Range. Network 132.178.227.0, broadcast 132.178.227.127, usable .1 to .126, 126 hosts.
.200? No: 200 = 1|1001000, first host bit is 1, so it is in 132.178.227.128/25. Private? No. RFC 1918 is 10/8, 172.16/12 and 192.168/16. Onyx is public, with no NAT between it and the Internet. Worth contrasting with their laptops at home.

Grading

Pass/fail, 20 points. Pass when every box has something in it and the round 1 arithmetic was attempted in binary. Wrong predictions are fine; that is what they are for.

Round 3 · how big can a datagram be?

ip link show eno12399np0  (look for mtu 1500)  then two pings
PING 132.178.227.1 (132.178.227.1) 1472(1500) bytes of data.
1480 bytes from 132.178.227.1: icmp_seq=1 ttl=254 time=0.654 ms

PING 132.178.227.1 (132.178.227.1) 1473(1501) bytes of data.
ping: local error: message too long, mtu=1500
Point at 1472(1500): ping itself prints the payload and the full datagram size.
Biggest payload. 1,472 bytes. 1,472 + 8 (ICMP header) + 20 (IPv4 header, no options) = 1,500.
Q2. The 28 bytes are the ICMP and IPv4 headers. The error came from Onyx's own kernel: with don't fragment set and a 1,501 byte datagram, it refused to send, so nothing left the machine. Without -M do, Onyx (or any router with a smaller MTU on the way) fragments, and only the destination host reassembles, using the identifier, flags and offset fields. IPv6 routers never fragment.
Fast group  Why ttl=254 and not 255 from a gateway on the same link? Not confirmed; a virtual gateway address answered by a router behind it is the likely story. Discussion only.

Say "Hop 13 is the server, so that is 12 routers. Five of them never answered, and the packets went through them anyway."
Count. 13 hops, so 12 routers before the server. 5 hops said no reply (2, 6, 7, 8, 9).
Q3. tracepath sent a datagram with TTL 3. The first two routers each decremented it, the third decremented it to zero, dropped it, and sent back an ICMP time exceeded message whose source address is hop 3. The no reply routers forwarded traffic fine (later hops answered) but do not send, or rate limit, or filter, those ICMP messages. Forwarding and answering ICMP are separate jobs. pmtu 1500 is round 3's MTU, discovered along the path.
Optional. asymm means the reply came back over a different number of hops than the probe went out: the return path is not the same path.

Exit question

Any field outside the destination address, with an action. Examples: a firewall matching destination port 23 and dropping it; NAT matching the source address and port and rewriting them; a load balancer matching destination port 443 and picking a server; a rate limiter matching the protocol field (ICMP). Generalized forwarding is exactly match plus action over any header fields (sections 4.4 and 4.5).
