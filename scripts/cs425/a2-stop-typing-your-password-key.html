Steps 1 to 4 · keys and multiplexing

Cold versus warm, measured from a laptop
$ ssh -O exit onyx ; time ssh onyx true
cold (full handshake): 1105 ms

$ time ssh onyx true
warm (reused master):  248 ms

$ ping -c 3 onyx.boisestate.edu
rtt min/avg/max = 31.4/33.7/35.3 ms
Say: about 1.1 seconds against a 31 ms round trip. Ask what the extra time bought: a TCP handshake, a version exchange, a key exchange, and authentication. Accept any estimate in the range of a handful to a few dozen round trips. Do not let them conclude it is all network time: key exchange is arithmetic, and on a fast link the crypto dominates. The warm case is roughly 4x faster and still not zero, because starting a process on the far end is not free.
Q1. Any estimate from about 5 to about 30 round trips passes, with something named: handshake, version exchange, key exchange, authentication. The largest speedup is normally the laptop with the slowest link or the slowest CPU; either explanation is fine if it matches their numbers.

Where step 2 goes wrong

  • No ssh-copy-id on Windows. Manual procedure is on the page; have it on the board before you start step 2, not after the first hand goes up.
  • Still asks for a password. Permissions, nearly always. On Onyx: chmod 700 ~/.ssh; chmod 600 ~/.ssh/authorized_keys. On the laptop: chmod 600 ~/.ssh/config ~/.ssh/id_ed25519. Run ssh -v onyx and read the line after "Offering public key".
  • Windows and ControlMaster. Multiplexing is unreliable on Windows builds of OpenSSH. A Git Bash student may see a warning or two cold timings. Write both down, note the OS, move on.

Steps 5 to 8 · the function

Loaded and proven
$ cat ~/.bash_profile
if [ -f ~/.bashrc ]; then
        . ~/.bashrc
fi                                         ← the login shell sources .bashrc

$ head -20 ~/.bashrc
(no [ -z "$PS1" ] line on Onyx)

$ type probe
probe is a function

$ probe example.com 80
connect=0.033370 total=0.057519 code=200

$ ssh onyx probe example.com 80     # non-interactive, from the laptop
connect=0.033370 total=0.057519 code=200
Say: the last one is the one that matters. That shell had no prompt and no terminal, and the function was still there, because bash reads ~/.bashrc when a remote shell daemon starts it and Onyx has no guard line stopping it. Verified on Onyx, so if a student's fails, the cause is in their file, not in the machine. Usual causes: the edit did not save, or it went into a different file.
Q2. A guard line returns from ~/.bashrc before the function is defined whenever the shell is not interactive, and ssh host command is not interactive, so the function never exists in that shell. Any sentence with "not interactive" and "returns before" or "never reaches" passes.
Q3. An alias is textual substitution at the front of a command, so the words you type can only land at the end. There is no way to put the second word into the middle of a URL. A function has positional parameters, $1 and $2, and that is the whole reason probe is a function.

Rescue

  • A broken ~/.bashrc can cost a student their shell. ssh onyx -t 'bash --norc' gets them back in to fix it.
  • vi. On the board before step 3 and left there: i to type, Esc to stop, :wq save and quit, :q! bail out, G end of file, o new line below. Typed before i and things went strange: Esc, :q!, start over.
  • Missed the class. The page is written to be done alone; point them at it and at A3's note that probe can be pasted at the prompt for one session.
Pass bar: a row per member with two timings, and something written under each of the three questions. Award 20 or nothing.
