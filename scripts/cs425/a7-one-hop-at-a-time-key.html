Say "The IP address says where Onyx is. The MAC address says who Onyx is, wherever it goes."
Predict. Only the IP address changes. The MAC is flat and belongs to the card, not the location. That is the postal address versus social security number analogy from the notes.
OUI and bits. 6c:92:cf is Broadcom. The first byte 0x6c = 0110 1100: lowest bit 0 (unicast), next bit 0 (globally unique).
Fast group  The two DOWN ports start e8:cf:83, which is Dell: the ports built into the server. The Broadcom ports are an add-in card. Each card's two ports have consecutive addresses (...50, ...51), because a vendor hands out a block per card.
Phone. A randomized address has the second lowest bit of the first byte set (the first byte's hex digit pair ends in 2, 6, A or E), so it is locally administered. Q1. Privacy. A fixed hardware address lets every Wi-Fi network, store and stadium recognize the same phone wherever it goes. A different made up address per network breaks that tracking.

Say "Line the generator up under the leftmost 1, XOR, repeat. When there is no 1 left in the first eight columns, the last three bits are R."
Predict. r = 3 bits, one less than the 4 bit generator.
R. 011. On the wire: 11010011 011. The receiver divides 11010011011 by 1011 and gets 000: no error.
Flip the third bit. 11110011011 leaves remainder 010, not zero, so the receiver drops the frame. Every single bit error is caught, since the generator has more than one term.
Fast group  Find an error the CRC misses. Any error pattern that is a multiple of G gets through: flip bits 2, 4 and 5 (pattern 01011000000, which is G shifted) and the remainder is 000.

Flooded. 2 of 5: frame 1 (unknown destination) and frame 4 (broadcast). The switch learns from the source address, never the destination, which is why frame 1 teaches it about A and not D.
Q3. B sees frames 1 and 4 (flooded) plus frame 3, which it sent. It never sees 2 or 5. Behind a hub B would see all five, because a hub repeats every bit out every port. That is why Wireshark on a switched network mostly shows your own traffic and broadcasts.

Exit question

ARP. An ARP request is a link layer broadcast, not an IP datagram, so a router has nothing to forward it on and it stops at the edge of the subnet. DHCP starts as a broadcast too, but on campus a DHCP relay on the router usually forwards it to a central server, so accept DHCP only if they explain why. DNS, TCP and HTTP are ordinary datagrams and cross routers all day.
