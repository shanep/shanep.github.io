Say "One character in, a completely different fingerprint out. Now, who can compute that fingerprint?"
Digits. Essentially all of them. A good hash changes about half its bits for any change to the input, so a one character edit gives an unrelated looking hash.
Q1. No: a plain hash proves nothing about who made it. Anyone, Trudy included, can hash the altered message, so Bob sees a matching pair. The MAC hashes the message with a shared secret, and Trudy does not have it, so she cannot produce a MAC that matches $90. Integrity needs a key. A MAC gives integrity and authentication but not non-repudiation, since both sides hold the secret (section 8.3).

Issuer. Let's Encrypt (intermediate YR1), good for 90 days. Short lives limit the damage from a stolen key, and renewal is automated.
Subject. The hosting company, Pantheon. www.boisestate.edu is in the Subject Alternative Name list, and the SAN is what a client matches against.
Q2. Each certificate is signed by the one above it, and Onyx can check each signature with the signer's public key. The chain ends at ISRG Root X1, which the server did not send: it is one of the 147 roots in /etc/pki/tls/certs/ca-bundle.crt, shipped by Red Hat with the OS. So Onyx trusts the OS vendor's choice of CAs, and the CAs' checking that the requester controls the name. Certificates move the trust problem to the CA, they do not remove it (section 8.3).

Point at the right hand column of the hex dump: the hostname, in the clear, in the first message.
Q4. The DNS lookup (normally unencrypted), the server's IP address and port, the hostname in the SNI field, when each connection happens and how long it lasts, and how many bytes go each way. That is often enough to tell what you are doing without reading a word. TLS protects the contents (section 8.6).

Typing yes trusted that the very first connection really reached Onyx: trust on first use. Nobody vouched for that key, and an attacker on that first connection would have been remembered instead. After that, SSH checks the saved key every time. Onyx never asks: openssl s_client trusts a key because a CA it already trusts signed a certificate binding that key to the name. One model trusts the first contact, the other trusts a third party.
