A1 · Application layerNames: Round 5 · nc

Round 5 · nc: be the client yourself

nc knows no protocol at all. It opens a connection and moves bytes, which means you get to be the protocol. That is exactly what P1 asks you to write.

nc -vz onyx.boisestate.edu 22     # something is listening
nc -vz onyx.boisestate.edu 9      # nothing is
PortWhat nc printed, word for wordHow long
22
9

Those are two completely different failures. Telling them apart is most of A2.

Speak HTTP by hand

{ printf 'GET / HTTP/1.1\r\nHost: example.com\r\nConnection: close\r\n\r\n'; sleep 3; } | nc example.com 80

Why the sleep 3? Onyx has nmap-ncat, which closes the connection the moment stdin runs out. Without the sleep, your request goes out and nc hangs up before the reply lands. Run it once without, add -v, and read the bytes sent versus bytes received line.

  1. What was the very first line the server sent back?
  2. Drop the Host: header and run it again. What changed, and why does HTTP/1.1 require it?
  3. Change every \r\n to \n. What does the server do? P1 is a mail client and SMTP has the same rule, so this is worth getting wrong now rather than at 2am in week 4.
A1 · Application layerNames: Round 6 · ping

Listen, and be listened to

You are all on one machine, so one of you can be the server. Bind to 127.0.0.1, never 0.0.0.0, and kill it when you are done.

PORT=$((10000 + $(id -u) % 20000)); echo "$PORT"
ss -ltn | grep ":$PORT" || echo "free"
nc -l 127.0.0.1 "$PORT"          # blocks, waiting. Another member: nc 127.0.0.1 <PORT>

Whose port did you connect to, and what did you send? Confirm with ss -ltn that nothing of yours is still listening afterwards.

Round 6 · ping: the one that is not an application tool

Everything above spoke an application protocol. This one does not: ICMP rides directly in IP, and has no ports and no idea what a service is.

ping -c 5 onyx.boisestate.edu       # also try: -i 0.5   -s 1000   -W 2   -w 5   -n   -q
ping -c 3 example.com               # the host you fetched a page from in Round 4
TargetPacket lossDid curl reach it earlier?

Those two rows contradict each other. That contradiction is the whole point of this round, and of Round 3 in A2.

  1. What layer does ICMP live at, and what does that mean about ports?
  2. Onyx answers ping. Does that prove the SSH server on it is running? Why not?
  3. example.com does not answer ping, and also served you a web page. So what did the failed ping actually tell you? Name at least two different things that could produce that result.
A1 · Application layerNames: Round 7 · .bashrc

Round 7 · Make it stick

In A2 you will type one curl command more than a dozen times. Teach the shell a new word instead, and make it survive a logout.

1. Find out where bash reads its configuration

On Red Hat a login shell reads ~/.bash_profile, and the default one sources ~/.bashrc. Confirm it on your own account.

cat ~/.bash_profile
head -20 ~/.bashrc

Is there a line near the top of ~/.bashrc like [ -z "$PS1" ] && return? On Onyx there is not, and that is why step 4b works. On a machine that has one, the file gives up immediately for any shell that is not interactive. Write what you found.

2. Add the function, at the bottom of ~/.bashrc

# CS425: probe a host and port, report how long each phase took
probe() {
    curl -sS -o /dev/null -m 8 \
        -w 'connect=%{time_connect} total=%{time_total} code=%{http_code}\n' \
        "http://$1:$2/"
}

3. Load it and check that it took

source ~/.bashrc
type probe          # should say "probe is a function"
declare -f probe    # prints the definition back
probe example.com 80

What did probe example.com 80 print?

4. Prove it is permanent, which is the actual point

a. Log out of Onyx completely, log back in, and run probe example.com 80 without sourcing anything. Did it work?

b. From your laptop: ssh onyx probe example.com 80. No prompt, no terminal, just one command. It should work, because bash reads ~/.bashrc when a remote shell daemon starts it. In one sentence: why would this fail on a machine whose ~/.bashrc began with the guard line from step 1?

c. Why a function and not an alias? Try alias probe='curl ...' and see what happens when you need $1 and $2 in the middle of the command.

If you finish early

Put the same function in your laptop's shell configuration so it is there whichever machine you work from in A2: ~/.zshrc on macOS, ~/.bashrc on Linux and in Git Bash. Then write a second function probes that prints the full five phase breakdown from Round 4 instead of two numbers.
