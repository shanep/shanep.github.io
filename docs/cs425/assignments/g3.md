## Background

`src/stack/netif.h` is the seam the whole project rests on. A `netif_t` can send a frame,
receive a frame and tell you what time it is. In your tests the simulator provides it with
`sim_netif()`, and in G4 your driver provides it. Nothing above this line knows the
difference.

An Ethernet frame is 14 bytes of header and up to `ETH_MTU` bytes of payload, and short
frames are padded out to `ETH_MIN_FRAME`. To send an Internet Protocol (IP) packet you need
the hardware address of the next hop, and ARP is how you find it:
[RFC 826](https://www.rfc-editor.org/rfc/rfc826) describes a broadcast that asks who has an
address, and a reply from whoever does.

## Task 1 - Ethernet and ARP

Implement everything in `src/stack/eth.h`.

`eth_input()` drops anything malformed and anything not addressed to this host or to the
broadcast address. It answers ARP requests for this host's address, and it learns from the
replies it gets.

`eth_send_ip()` is where the layers meet. If the next hop is in the cache, the packet goes.
If it is not, you send an ARP request and hold on to this one packet, replacing any packet
already held for that address, and send it when the answer comes back. Losing the older
packet is fine, because Transmission Control Protocol (TCP) retransmits and the Domain Name
System (DNS) client retries.

`eth_tick()` retries a request every `ARP_RETRY_MS`, gives up after `ARP_MAX_TRIES` and
expires an entry after `ARP_TTL_MS`. A cache of `ARP_CACHE_SIZE` entries can fill up, so
decide what gets thrown out and say so in your README.

## Task 2 - Wire it together

Implement `net_init()` and `net_poll()` in `src/stack/stack.c`.

`net_init()` starts every layer and connects them: Ethernet hands packets to IP, IP hands
protocol 6 to TCP and protocol 17 to the User Datagram Protocol (UDP), and each layer's
output function calls the layer below it. It also adds the routes from the configuration,
one for the attached network and a default route if there is a gateway.

`net_poll()` tells each layer the time and takes the frames that have arrived. It never
blocks, and calling it over and over is what makes everything run.

The `net_stack_t` struct is over a megabyte, so make it static. A kernel stack will not
hold it, and neither will the stack of a test you run under Address Sanitizer.

## Task 3 - Run the whole stack

`src/main.c` is provided, and it can finally run. It moves a file between two hosts over
the simulator and prints the congestion window as comma separated values (CSV).

```bash
make release
./build/release/myapp -n 2000000 -l 0.003 -q 60 -s 2 > cwnd.csv
```

```text
2000000 of 2000000 bytes in 11253 ms, identical
retransmits 5, fast retransmits 5, timeouts 0
link: sent 2771, lost 8, queue drops 0, reordered 0, duplicated 0, corrupted 0
```

Your numbers will be close to these and not exact, because they depend on your choices about
timers and acknowledgments. `identical` is the part that has to match. The flags are
`-n` bytes, `-d` delay in milliseconds, `-r` bytes per millisecond, `-q` queue length in
packets, and the rates `-l` loss, `-u` duplicates, `-o` reordering and `-c` corruption, with
`-s` the seed.

The CSV is the picture of Reno from Chapter 3, drawn by your own code. Here are the first
lines of it and the moment of the first loss, from the reference solution.

```text
ms,state,cwnd,ssthresh,flight,rto_ms,retransmits,fast_retransmits,timeouts
84,4,4380,65536,0,252,0,0,0
134,4,5840,65536,5840,239,0,0,0
142,4,7300,65536,7300,239,0,0,0
...
4144,4,78953,65536,62780,711,0,0,0
4184,4,36500,32120,64240,711,1,1,0
```

Look at the last line. With 64240 bytes in flight, `ssthresh` drops to half of that, and
`cwnd` to `ssthresh` plus 3 segments. Plot `cwnd` over time with a tool you like, and put the
picture in your repository as `cwnd.png`. Run it again with enough loss to see timeouts, and
add that picture too.
