# G0 - Boot the Kernel

**Week 3 · 20 points · about 4 hours · submit in Canvas**

## Overview

This is the first milestone of the CS 525 project. By the end of the semester you will
have written a whole network stack in C, from the driver for a network card up to a web
server, and it will boot on its own in QEMU, the Quick Emulator, with no operating system
under it. You will `curl` a page out of it.

G0 is short on purpose. You prove your tools work on both systems while you still have
months to fix them, and you write the one function every layer above needs.

## Background

A unikernel is one program linked with just enough kernel to boot, so there is no
scheduler, no processes and no C library. The starter gives you that kernel, about 420
lines of it: a boot stub, a serial console, a timer, and enough Peripheral Component
Interconnect (PCI) code to find a network card. It runs one loop forever. There are no
interrupts and no threads, so there is no locking to think about.

The kernel is 32 bit x86, and QEMU boots it directly with its `-kernel` flag. Your stack
is plain C with no allocation and no calls into libc beyond `memcpy` and friends, so the
same code also builds as an ordinary Linux program, where it gets Unity, coverage and
Address Sanitizer.

The Internet checksum from [RFC 1071](https://www.rfc-editor.org/rfc/rfc1071) is how IP,
ICMP, UDP and TCP each notice a damaged packet. You add up the data as 16 bit big endian
words, fold any carries back into the low 16 bits, and take the one's complement. A
receiver runs the same sum over the packet with the checksum in it and gets zero.

## Task 1 - Build and boot

Open your repository in a Codespace and build everything. A new Codespace keeps installing
QEMU for a minute or two after it opens, so if `make run` says `command not found`, give it
a minute and try again.

```bash
make all
make run
```

Your kernel boots, says hello and then panics, because the driver is not written yet. That
is the right answer for now. QEMU quits on its own, so `make` reports an error. Once your
driver works in G4 the kernel keeps running, and you press `Ctrl-a` and then `x` to leave.

```text
hello from the unikernel
panic: virtio-net would not start
make: *** [Makefile:134: run] Error 3
```

Now do the same thing on Onyx. See `docs/onyx.md` in your repository for what to check
first. Paste both transcripts into your `README.md`.

::: warning

The kernel needs `gcc -m32`, so `make kernel` only works on 64 bit x86. A Codespace and
Onyx are both fine. On an Apple Silicon Mac, it will not build outside of an emulated
x86 container, so do this work in your Codespace.

:::

## Task 3 - Write the checksum

Implement all three functions in `src/stack/checksum.c`. They are declared in
`src/stack/port.h`, and the comments there are the specification.

- `net_checksum_add()` adds a buffer to a running sum.
- `net_checksum_finish()` folds the sum into 16 bits and takes the one's complement.
- `net_checksum_pseudo()` adds the IPv4 pseudo-header that TCP and UDP checksums cover.

The sum comes in pieces because TCP and UDP checksum the pseudo-header and then the
segment. An odd length buffer gets a zero byte after its last byte, and only the last
piece is allowed to have an odd length. One fold is not always enough, since folding can
carry again, so make sure and loop until nothing is left above bit 15.

The sample in RFC 1071 is the bytes `00 01 F2 03 F4 F5 F6 F7`, which come out to `0x220D`.
That is the smoke test, and it does not touch any of the hard parts. Write your own tests
in a new file in `tests/`, and call them from `tests/main-test.c`. Test an odd length, the
same data split into pieces, a sum that carries twice, and a pseudo-header you worked out
by hand.

from system or library calls, and there are none in this file.
