# P4 - Packet Capture and Analysis

**Week 13 · 100 points · about 8 hours · submit in Canvas**

## Overview

You have spent the semester reading about headers. Now you are going to parse real
ones. Given a packet capture, walk each frame down the stack: Ethernet, then IP,
then TCP or UDP, and report what you find. This is the "day in the life of a web
request" from chapter 6, except you extract it from bytes yourself.

Fork the [starter repository](https://github.com/shanep/makefile-project-starter)
using the **Use this template** button and name your copy `cs425-p4`.

::: danger

Your code must compile on **GitHub Codespaces and Onyx**. If it compiles on only
one of them you will receive a zero even if it works on the other.

:::

## Learning Outcomes

- 5.2 Trace an end-to-end request through ARP, DHCP, switching, and routing
- 1.1 Explain encapsulation and how a message is transformed as it moves down and
  up the protocol stack
- 7.2 Produce code free of memory leaks and out-of-bounds accesses

## Task 1 - Read a pcap file

Parse the pcap file header and iterate the records. Do not assume the file is well
formed. A truncated capture must produce an error, not a read past the end of your
buffer.

## Task 2 - Parse the link and network layers

For each frame, decode the Ethernet header and dispatch on the EtherType. Decode
IPv4 headers, including the variable length options field, and handle ARP.

## Task 3 - Parse the transport layer

Decode TCP and UDP headers. For TCP, report the flags, sequence number, and window.
Verify the checksums.

## Task 4 - Report and cross-check

Produce a per-flow summary, then open the same capture in
[Wireshark](https://www.wireshark.org/) and confirm your numbers agree with what it
reports. Any disagreement is a bug in your parser, and finding it is the assignment.
