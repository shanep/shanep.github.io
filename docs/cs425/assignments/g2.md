You are going to write the network layer and the rest of the transport layer: Internet
Protocol version 4 (IPv4), routing, Internet Control Message Protocol (ICMP), User Datagram
Protocol (UDP), and a Domain Name System (DNS) client on top of it.

Keep working in your `cs525-g` repository and set `MILESTONE` to 2 in `tests/main-test.c`.

## Background

The interfaces are fixed, in `src/stack/ip.h`, `udp.h` and `dns.h`. The comment on each
function is its specification, and the `ip_t`, `udp_t` and `dns_t` structs are yours.

This host never forwards a packet, since it is not a router. It only sends its own packets
and takes in the ones addressed to it. Everything above IP registers a handler for its
protocol number with `ip_set_handler()`, so IP never needs to know that UDP or TCP exist.

The specifications are [RFC 791](https://www.rfc-editor.org/rfc/rfc791) for IPv4,
[RFC 792](https://www.rfc-editor.org/rfc/rfc792) for ICMP,
[RFC 768](https://www.rfc-editor.org/rfc/rfc768) for UDP, which is three pages long, and
[RFC 1035](https://www.rfc-editor.org/rfc/rfc1035) for DNS. Each RFC is a Request for
Comments. [RFC 1122](https://www.rfc-editor.org/rfc/rfc1122) has the rules for how a host
should behave.

## Task 1 - IPv4 and routing

Implement `ip_init()`, `ip_output()`, `ip_input()`, `ip_set_handler()`, `ip_route_add()`,
`ip_route_lookup()` and `ip_stats()`.

Every packet that comes in is a chance for somebody to crash you, so `ip_input()` has to
check everything before it trusts anything: the version, a header length of at least 20
bytes, a total length that fits in what actually arrived, and the header checksum. Count
each reason in `ip_stats()`.

Two rules are easy to miss. A frame can be longer than the packet in it, because Ethernet
pads short frames, so only trust the total length in the header. You also do not reassemble
fragments, so count them and drop them. Modern hosts avoid fragments anyway, and writing a
reassembly buffer with no allocator is a project of its own.

`ip_route_lookup()` is longest prefix match, with the same trap as P3: `/0` must not shift
by 32. A lookup over a list of 8 routes is fine.

## Task 2 - ICMP

Implement `ip_ping()`, `ip_ping_replies()` and `ip_reply_unreachable()`, and answer echo
requests.

An echo reply is the request sent back with the addresses swapped, the type changed and the
checksum recomputed. `ip_reply_unreachable()` sends a destination unreachable about the
packet being handled, which includes that packet's header and its first 8 bytes. RFC 1122
says to stay quiet about broadcasts and about ICMP itself, or two hosts can get stuck
sending errors about each other's errors.

## Task 3 - UDP

Implement `udp_init()`, `udp_bind()`, `udp_unbind()` and `udp_send()`.

The checksum covers the pseudo-header you wrote in G0. A checksum of zero on the wire means
the sender did not compute one, so accept it, and if yours comes out to zero send `0xFFFF`
instead. A datagram for a port nobody has bound gets an ICMP port unreachable, which is what
`traceroute` depends on.

## Task 4 - DNS

Implement everything in `src/stack/dns.h`.

This is a client for address records, one lookup at a time, and it never blocks. You start
a lookup with `dns_resolve()` and ask how it is going with `dns_result()`. `dns_tick()`
resends the query every `DNS_RETRY_MS` and gives up after `DNS_MAX_TRIES`, because UDP may
well have lost it.

A DNS message comes from the network, so it can lie. `dns_read_name()` follows the
compression pointers from RFC 1035 section 4.1.4, and a pointer can point at itself. Your
kernel has no way to recover from a hang, so a loop or a pointer out of the message has to
come back as an error. The simplest way is to only ever allow a pointer to go backwards.

`dns_parse_response()` must check the ID and the name in the question, or anyone who can
guess a port can tell you where `example.com` lives. Test it with a message you built by
hand, and with a real one. Run `dig +noedns example.com A` while Wireshark is capturing,
and copy the bytes of the response into your test.
