# P2 - Reliable Data Transfer

**Week 7 · 100 points · about 10 hours · submit in Canvas**

## Overview

You are going to build a reliable data transfer protocol on top of UDP: an
unreliable channel that loses, reorders, and corrupts what you hand it. This is the
rdt2.2 / rdt3.0 progression from chapter 3, implemented rather than drawn on a
whiteboard. By the end you will understand why TCP is shaped the way it is.

Fork the [starter repository](https://github.com/shanep/makefile-project-starter)
using the **Use this template** button and name your copy `cs425-p2`.

::: danger

Your code must compile on **GitHub Codespaces and Onyx**. If it compiles on only
one of them you will receive a zero even if it works on the other.

:::

## Learning Outcomes

- 3.1 Implement a reliable data transfer protocol over an unreliable channel
- 3.3 Choose between TCP and UDP for a given application and defend the choice

## Task 1 - Sender and receiver over UDP

Implement a sender and a receiver that exchange a file over a UDP socket through a
provided channel simulator that drops, duplicates, and corrupts datagrams at a rate
you control on the command line.

## Task 2 - Checksums and acknowledgements

Detect corruption with a checksum, acknowledge what arrived, and retransmit what
did not. Handle the duplicate ACK case: a lost ACK is indistinguishable from a lost
packet from the sender's side, which is exactly why sequence numbers exist.

## Task 3 - Timeouts and pipelining

Add a retransmission timer, then move from stop-and-wait to a pipelined protocol
with a sliding window. Measure the throughput difference and report it.

## Task 4 - Testing, coverage, and leaks

Unity tests for every function in `lab.h`, 100% coverage, and a clean
`make leak-test`. Keep the protocol state machine separate from the socket calls so
it can be tested without a network.
